# Prefill 阶段 Token-Power 建模实验总结

## 实验设置

本实验用于分析 Prefill 阶段输入 token 长度对 GPU 功率、延迟和能耗的影响。实验固定 GPU 功率上限为 350W，仅改变输入 token 长度，并将输出长度限制为 1 token，以尽量隔离 Prefill 阶段。

实验数据目录：

`experiment_results/prefill_token_power_modeling/gpu1_350w_block_nocache_fixed_0_20000`

有效样本范围：

- 输入 token 范围：`1 - 20000`
- 前段重点范围：`1 - 3000`
- 全范围聚合点数：45 个 token 长度
- 全范围有效样本数：174 条
- 前段聚合点数：36 个 token 长度
- 前段有效样本数：156 条
- GPU：GPU 1
- 功率上限：350W
- Prefix cache：关闭
- 测量方式：block mode
- 每个 token 长度连续执行多个请求，以获得稳定功率窗口

## 图 1：0-3000 tokens 平均功率与输入长度关系

图路径：

`images_front_0_3000/prefill_power_polyfit.png`

该图展示了 Prefill 阶段完整测量窗口内的平均 GPU 功率随输入 token 数增加的变化趋势。在 `1 - 3000 tokens` 范围内，平均功率整体呈近似线性上升趋势。

线性拟合结果：

```text

R2 = 0.8320
```

典型数据：

| Input tokens | Avg power (W) |
|---:|---:|
| 1 | 168.955 |
| 512 | 228.147 |
| 1024 | 226.423 |
| 2048 | 252.146 |
| 3000 | 273.895 |

该结果说明，在短到中等输入长度范围内，Prefill 计算负载增加会带来较明显的平均功率提升。由于该指标包含整个 block 窗口内的功率均值，因此会受到请求间 GPU 空闲回落的影响，但仍能反映整体能耗核算中的平均功率水平。

## 图 5：0-20000 tokens 全范围功率分段建模

图路径：

`images/prefill_power_polyfit.png`

该图展示输入长度从 `1` 到 `20000 tokens` 的完整功率变化趋势。与前段不同，长输入区域功率逐渐进入平台区，因此全范围不适合使用单一线性或二次函数拟合。

分段拟合结果：

```text
input_tokens <= 3000:
avg_power_w = 0.0357623 * input_tokens + 184.6368

input_tokens > 3000:
avg_power_w = 9.56693 * ln(input_tokens / 3000) + 278.3868

combined R2 = 0.9198
```

全范围补充拟合结果：

```text
TTFT = 0.172293 * input_tokens + 25.4706
R2 = 0.9947

energy_per_request_j = 0.0512112 * input_tokens - 2.4559
R2 = 0.9945
```

典型数据：

| Input tokens | Avg power (W) | TTFT (ms) | Energy/request (J) |
|---:|---:|---:|---:|
| 3000 | 273.895 | 482.452 | 132.167 |
| 4000 | 277.249 | 634.358 | 175.917 |
| 8000 | 290.533 | 1261.030 | 366.418 |
| 10000 | 289.803 | 1657.740 | 480.482 |
| 20000 | 293.261 | 3671.180 | 1076.700 |

该图说明 Prefill 阶段功率变化具有明显的分段特征：在 `0 - 3000 tokens` 范围内功率随输入长度快速上升；超过约 `3000 tokens` 后，GPU 功率进入饱和平台区，继续增加输入长度主要增加执行时间和能耗，而不会显著提高功率。

## 总体结论

1. Prefill 阶段的 TTFT 与输入 token 数高度线性相关，说明输入长度是 Prefill 延迟的主要决定因素。
2. Prefill 阶段单请求能耗与输入 token 数也高度线性相关，适合作为能耗建模的核心指标。
3. GPU 功率在短到中等输入范围内随输入长度上升，但在长输入范围内逐渐进入平台区。
4. 因此，Prefill 阶段不适合使用单一全局二次函数建模功率；更合理的方式是采用分段模型：前段线性增长，后段饱和或对数增长。
5. 对于后续功率控制策略，Prefill 阶段可以基于输入 token 数进行分桶或线性映射：短输入使用较低功率，中等输入逐步提高功率，长输入进入平台区后无需继续显著提高功率上限。
